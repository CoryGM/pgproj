# Entity relationship diagrams (`--erd`)

`init`, `build`, `diff`, and `publish` take `--erd [path]`, which also writes an entity relationship diagram of the project's tables as [Mermaid](https://mermaid.js.org/). `document` always includes the diagram in what it writes.

The diagram comes from the project's SQL files, never from a database. `diff` and `publish` write it before they connect (so `publish --dry-run --erd` writes it too), and `init` draws it from the files it has just written. If the project has errors, nothing is written and a warning says so.

## Files

- **The diagram** is a bare `.mmd` file.
- **A companion `.md`** of the same path and base name is also written by `build`, `diff`, and `publish`. It links the `.mmd` and shows the diagram in a `mermaid` block, so GitHub, VS Code, and other Markdown viewers render it. `init` writes only the `.mmd`; its report (`--report`) links it.
- **A web page**, with `--erd-html`: a `.html` file of the same path and base name that draws the diagram in any browser, and from which the rendered image can be saved. The diagram is inside the file, but the page loads Mermaid (version 11) from the jsDelivr CDN, so it needs internet access when it is opened. It also lifts Mermaid's 50,000 character limit, so a large diagram that GitHub will not render still draws there.

A `.mmd` or `.md` opened straight in a browser shows only text: use a viewer that includes Mermaid (GitHub, GitLab, Azure DevOps wikis, a Mermaid extension for VS Code, or the Mermaid Live Editor), or ask for the page.

## Where the files go

- With no value, the file is `erd-<yyyy-MM-dd-HH-mm-ss>.mmd` (the time the command started, in UTC) in the directory of `pgproj.json`.
- A value is the file's path, relative to the directory of `pgproj.json` (not the current directory) unless it is absolute. Missing directories are created.
- A `.mmd` or `.md` extension is replaced by the right one for each file; any other extension, or none, is kept and `.mmd` is added. So `--erd docs/model` writes `docs/model.mmd` and `docs/model.md`.

Because the value is optional, `--erd` takes the next word as its path unless that word starts with `-`. To get the default name, put `--erd` last or directly before another option.

## What is drawn

- One entity per table, including partitions and typed tables; views and materialized views are not drawn.
- In a project with tenants, the template's tables are drawn once, in the stand-in schema (`tenant.orders`), beside the shared tables ([Schema-per-tenant databases](tenants.md)).
- Each column with its type and `PK`, `FK`, and `UK` markers.
- One relationship per foreign key, from the referenced table to the referencing one, labelled with the constraint name. A foreign key whose columns are all `NOT NULL` is drawn `||--o{`; one with a nullable column is drawn `|o--o{`, since the parent is optional.
- A foreign key to a table the project does not define goes to a bare entity named `schema.table (external)`.

Names: when all the drawn tables are in one schema, the schema is left off; otherwise entities are named `"schema.table"`. A character Mermaid cannot take in a name (a space, a dash) becomes `_`.

Types are shown as the model has them, with `pg_catalog.` and `public.` dropped (`public.citext` is `citext`), and `int8`, `int4`, `int2`, `bool`, `float8`, and `float4` written as `bigint`, `integer`, `smallint`, `boolean`, `double precision`, and `real`.

The file is the same for the same project whatever order its files are read in.

## Choosing schemas

`--erd-schemas a,b` draws only the tables in the schemas named; `--erd-exclude-schemas a,b` draws every table except those. Either takes a comma-separated list or the option repeated, and they cannot be used together. Both need `--erd`, and without them every table is drawn.

- `public` is drawn only if it is named.
- A schema the project has no table in is an error; `init` refuses it before writing anything.
- A foreign key from a drawn table to a table that is left out goes to an `(external)` entity. A foreign key from a table that is not drawn is not drawn.
- With one schema drawn, the names are plain: `--erd --erd-schemas policies` shows table names without the schema.

`--erd` followed directly by one of these options takes the default file name.

## A file that is already there

`--erd-existing overwrite|backup|keep` (only with `--erd`) says what to do:

- `overwrite` replaces it.
- `backup` renames it to `name.<yyyy-MM-dd-HH-mm-ss>.ext` (UTC, the time the command started) and writes the new diagram at the path.
- `keep` leaves it alone and writes the new diagram to that stamped name instead.

Without the option, a file an earlier `--erd` wrote is backed up, and any other file is kept, with a message saying so. That is what protects a hand-written `README.md` or notes file. A file counts as written by `--erd` when it has the line `Generated by pgproj --erd` near its top (a `%%` comment in the `.mmd`, an HTML comment in the `.md`). Naming a mode yourself overrides this, even for a hand-written file.

The `.mmd`, the `.md`, and the `.html` are handled together: if any of them exists, the choice covers all three with one stamp, so the page still links the diagram written with it. A stamp already taken gets `-2`, `-3`, and so on, so nothing is replaced silently. The files are written under temporary names and moved into place together, so a failure never leaves a new diagram beside an old page.

## Messages

- `Wrote ERD: <path>`, `Wrote ERD page: <path>`, and `Moved existing ERD file to: <path>` are progress lines, so `--quiet` leaves them out.
- When a file you wrote is kept and the diagram goes to another name, that line is written even with `--quiet`, because the diagram is not where you asked for it.
- A diagram over 50,000 characters gets a warning, since some viewers (GitHub stops at about that size) will not render it. It is written anyway.
- With `diff --format json`, these lines go to standard error.
